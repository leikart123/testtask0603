Usage

Сборка:
make

statgen
Генерирует тестовые входные файлы:
	•	input_a.bin
	•	input_b.bin
	•	expected.bin
запуск:
./bin/statgen

statmerge

Объединяет два дампа.
Что делает программа:
	•	загружает два входных файла
	•	объединяет строки с одинаковым id
	•	сортирует результат
	•	печатает первые 10 строк
	•	сохраняет результат в выходной файл
Запуск:
./bin/statmerge input_a.bin input_b.bin merged.bin

stattest

Запускает автотест:
	1.	генерирует входные файлы
	2.	запускает statmerge
	3.	проверяет результат
Запуск:
./bin/stattest

Идея реализации

В этом проекте я хотел попробовать подход morsel-driven execution, который используется в современных системах обработки данных и СУБД.

Основная идея разбивать работу на небольшие независимые части (morsels), которые могут обрабатываться воркерами, привязанными к OS threads. Такой подход позволяет строить конвейер обработки данных, где разные стадии могут выполняться параллельно.

Предполагаемый пайплайн выглядит примерно так:
file → morsels → workers → merge → sort → output
Планировалось, что:
	1.	один воркер читает порцию данных из файла и размещает её в буфере;
	2.	другой воркер забирает готовый буфер и обрабатывает записи, добавляя их в хэш-таблицу для объединения по id;
	3.	после подготовки данных выполняется сортировка результата;
	4.	итоговые данные порциями записываются в выходной файл.
Buffer pool используется как промежуточный слой между I/O и обработкой данных, что упрощает построение конвейера и позволяет разделить чтение и обработку.

В текущей версии:
	•	реализовано чтение и запись данных morsel-ами через buffer pool;
	•	обработка выполняется последовательно;
	•	объединение данных реализовано через сортировку и слияние соседних записей.

Полноценная версия такого подхода потребовала бы:
	•	hash-таблицу, пригодную для работы несколькими воркерами;
	•	scheduler для выполнения morsel-задач;
	•	конвейерное выполнение стадий чтения, обработки и записи.
